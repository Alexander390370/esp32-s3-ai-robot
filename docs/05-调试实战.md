# 调试实战记录

> 2026-11-05 一整天从「能跑」到「能用」的完整排查过程。
> 这里记的是**真实踩过的坑**，每个都有现象、根因、修法。

## 一、JSON 解析漏了一个字符，所有动作指令失效

### 现象

```
网页遥控：方向键按了没反应
对话：能用（AI 回复 + 语音播报正常）
串口日志：[CMD] {"action": "move_forward", ...}  ← 消息收到了
           [心跳] ... 动作=                                ← 但 action 是空的
```

**最迷惑的地方**：MQTT 消息收到了、JSON 格式也对、代码逻辑看着没问题，
但就是解析不出来。

### 根因

```cpp
static bool jsonGetString(const String &json, const char *key, String &out) {
  int p = json.indexOf(k);
  p = json.indexOf(':', p + k.length());   // p 现在指向冒号
  if (p < 0) return false;
  while (json[p] == ' ' || json[p] == '\t') p++;   // ❌ 少了 p++
  if (json[p] != '"') return false;                 // 冒号 != 引号 → 返回 false
  ...
}
```

`p` 还指着冒号本身，`while` 循环第一次判断 `json[p]==':'` 不成立就退出了。
后面的 `json[p] != '"'` 直接返回 false，`action` 保持空字符串。

### 修法

```cpp
p++;    // ⚠️ 跳过冒号本身
while (json[p] == ' ' || json[p] == '\t') p++;
```

`jsonGetInt` 有一模一样的 bug，一起修。

### 为什么对话能用？

对话走的是 `speech` → PC 端 TTS → `robot/speak`，**不经过这个解析**。
所以「对话能用但遥控不行」这个现象反而成了定位线索。

## 二、HTTP 响应双重 JSON 编码，网页读不到状态

### 现象

```
网页状态区全是 "-"
距离 -    人体 -    光线 -    信号 -
```

但 `curl` 直接请求 `/api/state` 能看到完整数据。

### 根因

```python
def _json(self, status, data):
    raw = json.dumps(data, ensure_ascii=False).encode("utf-8")   # ❌
```

`handle_http()` 返回的**已经是 JSON 字符串**，`_json()` 又 `json.dumps` 了一次：

```
"{\"state\": {\"dist\": 43, ...}}"    ← 外面多了一层引号
```

前端 `JSON.parse()` 拿到的是**字符串**而不是对象，
所有字段读出来都是 `undefined`。

### 修法

```python
def _json(self, status, data):
    if isinstance(data, (dict, list)):
        raw = json.dumps(data, ensure_ascii=False).encode("utf-8")
    else:
        raw = str(data).encode("utf-8")    # 已经是 JSON 字符串，直接发
```

### 排查技巧

用原始 socket 发请求，看 body 的**第一个字符**：

```python
s.sendall(b"GET /api/state HTTP/1.0\r\n\r\n")
# body 以 { 开头 = 正常
# body 以 " 开头 = 双重编码
```

## 三、SAPI 回退时没初始化 COM，edge 失败就彻底没声音

### 现象

```
[TTS] edge 第 1 次失败: ClientConnectorError
[TTS] edge 第 2 次失败: ClientConnectorError
[TTS] edge 失败，回退 SAPI
[TTS] SAPI 不可用: (-2147221008, '尚未调用 CoInitialize。')
[语音] 合成失败，只下发文字        ← 这句完全没声音
```

### 根因

`reply()` 跑在**子线程**里，Windows 的 COM 要求**每个线程单独初始化**。
主线程初始化过不代表子线程能用。

### 修法

```python
def _synth_sapi(self, text):
    co_inited = False
    try:
        import pythoncom
        pythoncom.CoInitialize()      # 每次进来先初始化
        co_inited = True
        ...
    finally:
        if co_inited:
            pythoncom.CoUninitialize()
```

## 四、IPv6 路由不通，edge-tts 成功率只有 33%

### 现象

**音色时好时坏**：短句听起来是甜甜的女声，长句听起来是机械的女声。

```
[TTS] edge 第 1 次失败: ClientConnectorError
[TTS] edge 失败，回退 SAPI
```

### 排查

```python
# 连续测 8 次
成功 2/6，每次约 1.9 秒
```

DNS 解析发现返回了 **AAAA 记录**：

```
speech.platform.bing.com → 2620:1ec:33::10  (IPv6)
                         → 150.171.28.10    (IPv4)
```

本机有 IPv6 地址（`2408:8409:...`），aiohttp 优先尝试 IPv6，
但到微软服务器的 IPv6 路由不通 → `ClientConnectorError`。
重试时偶尔落到 IPv4 才成功。

### 修法

进程启动时 patch `socket.getaddrinfo`，优先返回 IPv4：

```python
_orig_getaddrinfo = socket.getaddrinfo

def _ipv4_first_getaddrinfo(host, port, family=0, type=0, proto=0, flags=0):
    results = _orig_getaddrinfo(host, port, family, type, proto, flags)
    v4 = [r for r in results if r[0] == socket.AF_INET]
    return v4 if v4 else results

socket.getaddrinfo = _ipv4_first_getaddrinfo
```

**效果对比：**

| | 成功率 | 单次耗时 |
|---|---|---|
| 修之前 | 2/6（33%） | 1.9 秒 |
| 修之后 | **8/8（100%）** | **1.3 秒** |

进程级生效，`edge-tts` / `requests` / `paho` 全部受益。

## 五、扬声器滋滋电流声

### 现象

```
改成软件音量 150% 后：
喇叭发出滋滋滋的电流声，听不到人声
```

### 根因

数字放大导致**削波**：

```cpp
int32_t v = (int32_t)src[i] * 150 / 100;
if (v > 32767) v = 32767;      // 大量采样被压平到这里
```

正常语音峰值约 20000-30000，乘 1.5 后变 30000-45000，
超出 int16 上限的部分**全部被压到 32767**，形成**方波**。
方波在音频里听起来就是滋滋声。

### 修法

```cpp
int m_volume = 100;    // 不要用软件放大
```

**想更响要改硬件**，不是改软件：

MAX98357 的 GAIN 引脚：

| GAIN 接法 | 增益 |
|---|---|
| 悬空 | 9dB |
| **接 GND** | **15dB**（+6dB ≈ 2 倍音量） |

## 六、喇叭只播第一块（1024 字节）

### 现象

```
[SPEAK] 收到 1024 字节，累计 1024
[SPEAK] 开始播放 1024 字节      ← 只播了这么点
[SPEAK] 播放完成
```

PC 端明明发了 58368 字节。

### 根因（两个 bug 叠加）

**bug 1：`spkReset()` 没清 `g_spkLast`**

```cpp
static void spkReset() {
  free(g_spkBuf); g_spkBuf = nullptr;
  g_spkLen = 0; g_spkCap = 0;
  // ❌ g_spkLast 没清
}
```

下一轮第一块到达时 `millis() - 旧值 > 900` 立刻成立 → 马上播放。

**bug 2：`publishPcm()` 上传后把 buffer 设回 2048**

```cpp
g_mqtt.setBufferSize(CHUNK + 512);   // 上传时 30512
...
g_mqtt.setBufferSize(2048);          // ❌ 恢复成 2048
```

但 SPEAK 每块是 **8192 字节**，buffer 只有 2048 根本收不下 → 丢包。

### 修法

```cpp
// 1. 用显式状态标记，不依赖时间戳
static bool g_spkActive = false;

static void spkReset() {
  ...
  g_spkLast = 0;
  g_spkActive = false;    // 关键
}

// 2. 播放条件
if (g_spkActive && g_spkLen > 0 && millis() - g_spkLast > 900) { ... }

// 3. 恢复 buffer 时用 32768，不是 2048
g_mqtt.setBufferSize(32768);
```

## 七、VAD 阈值太严，说话检测不到

### 现象

```
[对话] 检测到说话 (rms=16219, 阈值=15975)
[对话] 太短忽略 (说话 100ms)
```

检测到了，但只持续 100ms 就被判「太短」丢弃。

### 根因（两个问题）

**问题 1：阈值算法太严**

```cpp
阈值 = 底噪 × 3.0
```

环境噪声 4519 → 阈值 13557。说话声音稍微弱一点（16219）就卡在边缘，
一停顿立刻掉到阈值以下。

**问题 2：「太短」直接丢弃，没有宽容期**

```cpp
if (m_speechMs < VAD_MIN_SPEECH_MS) {
  m_state = LISTENING;
  m_buf.clear();       // ❌ 直接扔了
  return;
}
```

人说话有词间停顿，100ms 不代表说完了。

### 修法

```c
// 1. 阈值倍数降到 1.6
#define VAD_NOISE_MULT       1.6f
#define VAD_MIN_THRESHOLD     2500

// 2. 加 1.5 秒宽容期
if (m_speechMs > 0 && m_speechMs < VAD_MIN_SPEECH_MS) {
  if (m_silenceMs >= 1500) {
    // 真的没声了，才丢弃
  }
  return;    // 否则继续攒着
}
```

## 八、避障疯狂转圈

### 现象

```
[避障] 前方 15cm，让开
[避障] 前方 13cm，让开
[避障] 前方 8cm，让开
[避障] 前方 9cm，让开
```

车在原地疯狂抖动、自转。

### 根因

**避障动作耗时 830ms，但采样周期只有 300ms。**

```
采样（300ms）→ 触发避障 → 动作进行中 → 采样（300ms）→ 又触发避障
                              ↑
                        动作还没做完
```

而且超声波 `measure()` 要 3 次采样 × 60ms = 200ms，
在避障动作中途测到的距离是乱的。

### 修法

```cpp
// 1. 加锁，动作期间不重复触发
static bool g_avoiding = false;

static void autoAvoid() {
  if (g_avoiding) return;      // 锁住
  ...
  g_avoiding = true;
  // 执行完整动作
  g_avoiding = false;
}

// 2. 避障期间跳过超声波采样
if (!g_avoiding && millis() - lastSample >= SAMPLE_INTERVAL_MS) { ... }
```

**效果：22 秒内从十几次触发降到 2 次。**
