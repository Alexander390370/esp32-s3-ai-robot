# 语音链路

> 从麦克风到喇叭的完整链路，以及为什么每一步这样选。

## 一、完整链路

```
说话
  ↓
INMP441 麦克风（I2S，24 位）
  ↓ HTTP 无关，直接 I2S 读
ESP32-S3 采集 16kHz PCM
  ↓ MQTT（30000 字节/块）
PC 收到音频
  ↓
Whisper base 本地识别        ~0.5 秒
  ↓
DeepSeek API 生成回复        ~1.5 秒
  ↓
edge-tts 合成语音            ~1.9 秒
  ↓ MQTT（8192 字节/块）
ESP32 收到 PCM
  ↓ I2S
MAX98357 功放 → 喇叭
```

**端到端约 3.9 秒**（不含说话和播放时长）。

## 二、麦克风 INMP441

### I2S 配置要点

```cpp
cfg.bits_per_sample = I2S_BITS_PER_SAMPLE_32BIT;  // 必须 32 位
cfg.channel_format = I2S_CHANNEL_FMT_ONLY_LEFT;   // L/R 接 GND
cfg.communication_format = I2S_COMM_FORMAT_STAND_I2S;
```

**INMP441 是 24 位器件**，按 16 位读会位对齐错误，表现为「满幅削波」（峰值恒定 32768）。

读取时右移 14 位：

```cpp
int32_t v = raw[i] >> 14;
```

- 移太少（11）→ 直流偏置占满量程，削波
- 移太多（18）→ 有效信号太小，信噪比崩

### 硬件注意

| 引脚 | 接 | 注意 |
|---|---|---|
| VDD | 3.3V | **不能接 5V** |
| L/R | GND | **必须接，悬空会输出乱码** |

## 三、音频传输

### ⚠️ 坑 1：录音后半段全是垃圾

**原因**：按 1024 字节分块 + `delay(5)` 发 125 块，总共 625ms。
这期间 I2S 还在采集，DMA 缓冲被覆盖。

**修法**：

```cpp
const size_t CHUNK = 30000;   // 块大一点，块数少
...
delay(1);                     // delay 只给 1ms 让出 CPU
```

**验证方法**：分析接收到的 PCM，如果发现「中间某个位置之后全是尖峰」就是这个原因。

### ⚠️ 坑 2：喇叭只收到 826 字节

**原因**：`PubSubClient` 接收 buffer 默认 2048 字节，30KB 的块被截断。

**修法**：

```cpp
g_mqtt.setBufferSize(32768);   // 接收
```

注意 `setBufferSize` 的参数是 `uint16_t`，**最大 65535**，所以块大小不能超过 60000。

### ⚠️ 坑 3：喇叭只播一小段就停

**原因**：每块音频到达就调 `play()`，播的是碎片。

**修法**：累积到缓冲，600ms 没新块才一次性播：

```cpp
if (g_spkLen > 0 && millis() - g_spkLast > 600) {
  g_audio.play(g_spkBuf, g_spkLen);
  spkReset();
}
```

## 四、语音识别 Whisper

### 模型选择

| 模型 | 大小 | 中文准确率 | 速度 |
|---|---|---|---|
| tiny | 72 MB | ~30% | 0.3 秒 |
| **base** | **139 MB** | **~50%** | **0.5 秒** |
| small | 461 MB | ~70% | 1.0 秒 |
| medium | 1.4 GB | ~85% | 2.0 秒 |

**当前用 base**（速度和准确率平衡）。medium 下载容易中断，实测下载到 140MB 就 SHA256 校验失败。

### ⚠️ 坑：识别结果为空

whisper 的 VAD 很保守，音量偏低/背景噪声大的录音直接判「无语音」返回空字符串。

**修法**：

```python
model.transcribe(
    path, language="zh", fp16=False,
    no_speech_threshold=1.0,      # 极难判定为静音
    logprob_threshold=None,       # 不用置信度过滤
    temperature=0.0,
    without_timestamps=True,
)
```

### 预处理

INMP441 录出来的数据常有直流偏置和极低频漂移，先处理再喂给 whisper：

```python
# 去直流
dc = sum(samples) / n
centered = [s - dc for s in samples]

# 一阶高通（去 100Hz 以下的漂移）
alpha = 0.98
hp = []
prev_in = prev_out = 0.0
for s in centered:
    y = alpha * (prev_out + s - prev_in)
    hp.append(y)
    prev_in, prev_out = s, y

# 归一化到接近满幅
peak = max(abs(v) for v in hp)
gain = 24000.0 / peak
out = [int(v * gain) for v in hp]
```

## 五、语音合成

### 两个引擎

| 引擎 | 音质 | 速度 | 依赖 |
|---|---|---|---|
| **edge** | **真人级** | 1.9 秒 | 需联网 + ffmpeg |
| sapi | 机械 | 0.12 秒 | 本地，离线可用 |

**当前用 edge（zh-CN-XiaoxiaoNeural 晓晓）**，网络失败会自动回退 sapi。

### ⚠️ 坑 1：声音低沉发闷

```
TTS 合成 22050Hz，固件按 16000Hz 播 → 音调被拉低 27%
```

**修法**：TTS 强制输出 16kHz。

```python
# SAPI
fmt.Type = 18      # SAFT16kHz16BitMono

# edge：用 ffmpeg 转
ffmpeg -i input.mp3 -ar 16000 -ac 1 -acodec pcm_s16le output.wav
```

SAPI 的 Huihui 是 2010 年代的老语音。换 edge-tts。

## 六、自动对话模式（VAD）

不用手发 `REC`，直接说话就能对话。串口发 `CHAT` 开启。

### 工作原理

```
一直读 0.1 秒小块
  ↓
算 RMS 能量
  ↓
超过阈值 → 开始攒数据
  ↓
低于阈值持续 600ms → 认为说完 → 上传
  ↓
PC 处理，回语音
  ↓
播完回到监听
```

### 阈值自适应

开对话后先测 1 秒环境噪声（10 帧），取平均作为底噪。然后：

```cpp
阈值 = 底噪 × 3（但不低于 800）
```

这样不管麦克风增益多大都能自适应。

### 参数

`config.h`：

```c
#define VAD_THRESHOLD        1500    // 兜底阈值
#define VAD_NOISE_MULT        3.0f   // 底噪倍数
#define VAD_MIN_THRESHOLD     800    // 阈值下限
#define VAD_SILENCE_MS        600    // 静音多久算说完
#define VAD_MIN_SPEECH_MS     400    // 最短说话时长（防咳嗽）
#define VAD_MAX_RECORD_MS    6000    // 最长录音
```

### 调参方法

串口发 `CHAT` 开对话，然后：

1. 保持安静，看日志 `[对话] 校准完成：环境噪声 X，触发阈值 Y`
2. 正常说话，看 `[对话] 检测到说话 (rms=X, 阈值=Y)`
3. 如果安静时也触发 → `VAD_NOISE_MULT` 调大到 4-5
4. 如果说话不触发 → 调小到 2，或 `VAD_MIN_THRESHOLD` 降到 500
